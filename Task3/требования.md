# Безопасность 
###  Шифрование данных:
    Всё, что передаётся между системами, должно быть надёжно зашифровано. Используем современные стандарты, например TLS не ниже 1.3.  Данные, которые хранятся у партнёров, тоже должны быть защищены шифрованием.
    
    Доступ к API должен быть только у тех, кто действительно в нём нуждается. Никаких лишних людей или систем. Принцип «меньше прав — лучше»: доступ только к тем данным и функциям, которые необходимы для работы.

    Все данные поступющие из вне необходимо тщательно проверять. Никаких SQL-инъекций, XSS-атак и пр.

### Мониторинг:

    Все запросы и ответы должны логироваться, для анализа аномалий и разбора инцидентов.
    Настроен алертинг на анамалии.

### Защита от атак:

    Использовать WaF F5 для защиты от атак из вне.

### Контракты API:

Все соглашения по API должны быть проверены, чтобы не передавать лишние данные, особенно персональные.

Аутентификация:

    Для внешних систем используем OAuth 2.0 — это стандарт.
    Для внутренних интеграций подойдут API-ключи или JWT.
    Ограничить время жизни токенов.

Рзаграничение прав доступа

    У каждого пользователя или системы должны быть свои права доступа. Например, одни могут только читать данные, а другие — изменять.
    В OAuth 2.0 используем Scope, чтобы ограничить доступ к определённым ресурсам.


Стандарты API:

    Используем RESTful API или GraphQL — это удобно и понятно.
    Все API должны быть в одном стиле, например, использовать JSON для передачи данных. Принят Interface Agreement

API Gateway:    
    
    Внедряем шлюз для управления всеми API. Он будет: Направлять запросы куда нужно. Осуществлять мониторинг.
    Для надежности использовать Rate Linit и BulkHead.

Аналитика от системы "Умный дом":
    
    Обработку аналитических данных данных от системы "мный дом" осуществлять в ассинхронном режиме, используем асинхронное взаимодействие через очереди сообщений (например, RabbitMQ или Kafka).

### Форматы данных:
    
    Используем human readable форматы, такие как JSON. Все данные должны соответствовать заранее определённой структуре (например, JSON Schema).

### Обработка ошибок:

    Ошибки должны обрабатываться единообразно. Например, использовать HTTP-коды и понятные сообщения об ошибках.

### Документация:

Каждый API должен быть хорошо документирован. В документации должно быть:
    
    Описание всех endpoints.    
    Примеры запросов и ответов.

### естирование:

    Регулярно проверяем, как работают интеграции. Это включает нагрузочное тестирование и поиск уязвимостей.

### Надёжность:

    Система должна быть готова к сбоям. Для этого используем резервные каналы связи и, если возможно, несколько провайдеров.
